# Put the Fries in the Bag

A complete source implementation of the agreed playable prototype for a six-player Roblox restaurant. All world geometry and user interfaces are generated by the code. No paid assets, plugins, external models, or runtime packages are required.

## Open and play

1. Open **FriesGame.rbxlx** in Roblox Studio using **File > Open from File**.
2. Press **Play**. The restaurant is generated when the server starts; the edit viewport initially has no restaurant.
3. Hold or tap **PACK FRIES**, then press **SERVE BAG** when full.
4. Buy training under **UPGRADES**. After five sales, spend earned Tickets under **DELIVERY** and equip rewards under **GEAR**.
5. The first Lunch Rush starts 90 seconds after server startup when at least one profile is ready.

Studio uses explicitly labelled **memory-only test mode** by default. Stopping the test resets this mode's progress. This lets an unpublished place run without DataStore permissions.

Desktop shortcuts: **F** pack, **E** serve, **Q** start/stop folding. Touch users have on-screen buttons. **RETURN TO MY COUNTER** teleports you to your own station.

## Included

- Six automatically assigned counters, procedural customers, equipment models, and visible fry filling.
- Clicking/holding, online automatic filling, one full bag at a time, and serving.
- Cash and gameplay-earned Order Tickets.
- Permanent scooping and selling upgrades, each with 20 levels.
- Two gacha pools containing four rewards each, plus two starter items.
- Exact displayed odds, independent saved guarantee counters, and duplicate refunds.
- Inventory and explicit equipment selection.
- Regular, Loaded, and Golden fries with a persistent discovery index.
- A one-attempt perfect-fold timing action.
- Repeatable orders and a first-five-sales tutorial reward.
- A cooperative Lunch Rush with contribution requirements.
- UI layouts for desktop and mobile, including scrollable landscape-phone screens.
- Server-side validation, input rate limits, and bounded currency values.
- Profile validation, session locking, retrying saves, autosaves, disconnect saves, and shutdown saves.
- Automated tests and a reproducible place builder.

This is the prototype defined in our discussion. Future restaurant areas, promotions, offline production, trading, VIP competitions, custom audio, and paid products are not implemented. Visual assets are procedural prototype art.

## Saving and publishing

The runtime configuration is **src/shared/config/Runtime.luau**.

- **StudioUseDataStore = false**: Studio sessions use memory only.
- **StudioUseDataStore = true**: Studio accesses **FriesProfiles_TEST_v1**. First publish a separate test experience and enable **Studio Access to API Services** in its security settings.
- Published Roblox servers use **FriesProfiles_v1**, regardless of the Studio test flag.

Studio and live data use different store names. Change store names only intentionally: changing them makes the game read a different set of profiles. Keep an isolated test experience for persistence tests.

Set the experience's maximum player count to **6** before public release. The code declines extra players when all counters are assigned. Changing StationCount alone beyond six also requires adjusting the restaurant layout.

Profiles save approximately every 45–55 seconds and on exit. Like any networked persistence system, a server crash or service outage can lose work since the last successful save. An active lock prevents two servers from editing the same profile. If a profile cannot load safely, the server declines that session rather than replacing the saved data with defaults. After an unclean shutdown, a previous lock may take up to three minutes to expire.

Tickets are earned only through gameplay. This version contains no MarketplaceService purchases or paid random-item paths.

## Source layout

    src/
      shared/
        config/       Economy, equipment, variants, rush settings, runtime settings, action vocabulary
        domain/       Packing, folding, pricing, upgrades, gacha, orders, discoveries, rush, profile schema
        util/         Deep copy, weighted selection, token-bucket limiter
      server/
        Main.server.luau       Server composition and player lifecycle
        Network.luau           Remote transport
        services/             Data lifecycle, station ownership, action routing, private snapshots
        storage/              Session-locked persistence transactions
        world/                Geometry primitives, world layout, station layout, equipment cosmetics
      client/
        Main.client.luau       Client composition and remote subscriptions
        controllers/          Input handling
        ui/                   Shared UI elements/theme and one module per screen
    tests/                    Domain, persistence, and wiring tests
    tools/                    Place builder and test runner
    docs/                     Architecture, rules, and Studio acceptance checks

Every source file owns one responsibility. UI modules never award money, select random outcomes, or mutate server profiles. Domain modules do not create Instances, send network messages, or call DataStores. The server adapters connect these layers.

## Editing workflow

Choose one workflow for a work session:

**Studio:** edit the individual scripts in Explorer, then save the place. Scripts appear under ReplicatedStorage/FriesShared, ServerScriptService/FriesServer, and StarterPlayer/StarterPlayerScripts/FriesClient.

**Source files:** edit src/, then run the builder below and reopen the generated place. Changes made only inside Studio are not automatically exported back into src/. Rebuilding replaces the generated FriesGame.rbxlx.

An optional **default.project.json** is supplied for teams already using Rojo. Rojo is not required to open the supplied place or run the Python builder.

## Build

Python 3.9 or newer, standard library only:

    python tools/build.py

This embeds every source file into FriesGame.rbxlx and verifies XML parsing and exact source round-tripping.

Optional Rojo equivalent:

    rojo build default.project.json -o FriesGame.rbxlx

## Automated checks

Download the official Luau release tools from https://github.com/luau-lang/luau/releases and run:

    python tools/test.py --luau PATH_TO_LUAU_EXE --compiler PATH_TO_LUAU_COMPILE_EXE

See **VALIDATION.md** for the recorded results and **docs/STUDIO_TESTS.md** for the remaining engine checks. The source was compiled and tested in the standalone Luau VM, but the project has not been opened or playtested in Roblox Studio in this environment.
